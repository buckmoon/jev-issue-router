# 判定の偏りと精度の確認

2026-10-11に、共通エンジン・カタログ・Jev公式資料を調べ、合成タスクを実Jevで評価しました。
私有Issueやリポジトリ本文は送信せず、推薦先のOpenAI・Claude・Grokは実行していません。
実際に応答した評価モデルは `jev-1.13.0` でした。

## 調査で分かったこと

- 有効なGrok候補は1モデルです。同じモデルになるのは必然で、推論設定の違いを確認します。
- `max-quality` は各社の最上位モデルを固定する方針です。モデルが同じでも異常ではありません。
- `balanced` と `cost` はどちらも十分な能力の低コスト候補を優先します。
  実測料金やタスク完了結果が無いため、方針を変えても同じ候補になることがあります。
- 変更前も文言変更・複数コンポーネントの実装・決済競合で難易度は分かれていました。
  「常に同じ」という問題は合成タスク全体では再現しませんでした。
- 順序だけを反転すると、選定まで進んだ9件のうち3件で少なくとも1社の判定が変わりました。
  別途、研究タスクのreadinessも変わりました。集中した確率だけでは安定性を保証できません。
- 短い要望でも不足情報を能力不足とみなす指示、モデル間の境界が曖昧な説明、
  複数の判断をまとめた長い質問が、偏りを強め得る構造でした。原因の寄与率までは測定していません。

TypeSafeは、Jev 1.13の順序依存・字義通りの解釈・複雑な間接参照・無関係な長い入力の影響を
公表し、直接的な質問と順序を変えた確認を勧めています。
[公式の既知の制約](https://docs.typesafe.ai/model-jaggedness/jev-1.13)。
似た候補には隣接候補との境界を説明する方法もあります。
[公式Choiceガイド](https://docs.typesafe.ai/primitives/choice)。
confidenceは分布から計算する統計であり、正答やタスク完遂の証明ではありません。
[公式confidenceガイド](https://docs.typesafe.ai/confidence)。

## 実装した改善

1. 評価軸の質問を、入力のどの性質を判断するか直接示す文に変更しました。
   影響の大きさと推論の難しさを分離し、目的が明確な研究は解法が未知でも評価します。
2. 不足情報・unknownだけで上位へ寄せる指示を除き、本文の実際の判断負荷を優先します。
3. low/medium/high/xhigh/maxの境界と、有効なモデル間の使い分けを明記しました。
   モデルID・対応effort・公式確認日は変更せず、ルーティング説明の版のみ更新しています。
   使い分けは未校正の仮説で、公式の性能保証ではありません。
4. 選定時に各社の通常順と反転順を同じ呼び出しにまとめます。通常の2回の呼び出しを維持します。
   不一致は `recommendations.*.order_check` と画面・テキストの注意に出ます。
   主推薦は通常順の判定を保持します。保留を含め、逆順の判定と分布も保存します。
   API設定を機械的に採用する利用者は `order_check.consistent` を確認してください。
5. Python共通エンジン、iOSのSwift移植、同梱カタログ、表示を揃えました。
   フェイク応答による要求本文・結果JSON・表示の実行時一致もテストします。

順序反転も同じJevによる評価なので、独立した正解確認ではありません。
多数決・分布の平均・confidenceからの成功率算出・評価モデル間の自動切替は行いません。
低confidenceへの一律閾値も追加していません。用途ごとの実績で閾値を校正する必要があります。

## 合成タスクでの観測

10件のタスク（日本語/英語3組、研究、影響が大きい定型修正、短い要望、目的なし）を比較しました。
50個の評価軸に手作業で付けたラベルとの一致は変更前47個、変更後49個でした。
これは調査用の同じ小規模入力を使った確認で、独立した精度検証ではありません。
短い要望の検証方法は、ラベルのunknownに対し変更後simpleとなりました。

| 合成タスク | 最終版OpenAI | 最終版Claude | 最終版Grok |
| --- | --- | --- | --- |
| 文言変更 | Luna / low | Sonnet / low | 4.7 / low |
| API＋画面の一覧追加 | Sol / medium | Sonnet / medium | 4.7 / medium |
| 決済競合調査 | Sol / high | Opus / high | 4.7 / high |
| 新規アルゴリズム研究 | Astra / xhigh | Fable / xhigh | 4.7 / xhigh |

変更前は決済競合の日本語/英語でOpenAIとClaudeのeffortが違いました。
最終版の通常順では3組とも各社の主推薦が一致しました。
最終版でも反転順との不一致はOpenAI 4/9件、Claude 2/9件、Grok 0/9件で残っています。
研究や候補間の境界の曖昧さを、確定した正解として扱わないための確認です。
反転チェックは不一致を可視化するもので、不一致率の低下を保証しません。

7方針×文言変更/決済競合の14件も実評価しました。複数方針で同じ結果は残っています。
今回の入力だけでは `value` と `total-cost` を実測で区別できません。
モデルの実行成功、レビュー、再試行、所要時間を測っていないためです。

## 再現・継続評価する

インストールを更新して、新しいコマンドを有効にします。

```sh
.venv/bin/python -m pip install -e '.[dev]'
```

明示的な実評価（合成入力をTypeSafeへ送信して利用料が発生）:

```sh
.venv/bin/issue-model-benchmark --live --dataset examples/routing-benchmark.json --output benchmark.json
.venv/bin/issue-model-benchmark --live --dataset examples/routing-benchmark.json --policy quality --repeat 2 --output quality.json
```

Clefとの比較は `--evaluator clef` を付けて別途実行します。同じ本文で、自動切替はしません。
Workers AIは外部送信と利用料が発生し、localは指定したサーバーへ送信します。
通常テストはどちらにも接続しません。

保存結果の再集計（通信なし）:

```sh
.venv/bin/issue-model-benchmark --results benchmark.json --output summary.json
.venv/bin/issue-model-benchmark --results docs/results/jev-routing-20261011/after.json
```

データセットはJSON配列です。`id` は一意な短いASCII識別子、`issue` は通常のtitle/body/contextです。
`expected_assessment` に評価軸のラベルを指定できます。
同じ意味の言い換えや翻訳には同じ `equivalence_group` を付けます。
実績に基づく許容モデル/effortの集合を用意した場合は、次の任意項目も使えます:

```json
"expected_recommendations": {
  "openai": [{"model": "gpt-6.1-sol", "effort": "high"}]
}
```

レポートは本文を複製せず、入力ハッシュ・識別子・ラベル・結果と分布を保存します。
ラベルが無い推薦の `label_agreement` はnullです。「多様だから高精度」とは扱いません。
候補版・方針・評価モデルの指定/実応答モデルが違う結果は分けて集計します。
`--repeat` は1〜10、1データセットは最大100件です。回数に応じて評価利用量が増えます。

通常の2段階評価も、追加質問と説明によって入力トークンは増えます。
今回の10件では変更前/最終版の合計入力トークンは保存結果の `summary[].input_tokens` で比較できます。
API呼び出し数はどちらも19回（9件×2回＋保留1件×1回）です。

## 実際の選定精度を上げるために必要なデータ

代表的なタスクを訓練・調整用と未使用の検証用に分け、モデル名に引きずられずに完了を判定します。
同じ入力・作業時間枠・テストで候補を比較し、完了可否、重大な欠陥、レビュー修正、
所要時間、トークン/費用、再試行を記録してください。
テストを通して完了できる複数の候補があれば、許容集合としてラベル化します。
安い試行の進捗を目的にする方針と、検証済み完了を目的にする方針には別のラベルを使います。
調整後は未使用の検証集合でラベル一致・保留・順序感度・実コストを見て採用します。

推薦先のAPI実行や実Issueの外部送信は、このベンチマークコマンドの自動動作には含めません。
